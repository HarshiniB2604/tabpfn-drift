The project in simple terms

TabPFN is a pretrained model for spreadsheet-style data. It doesn't train on your data in the usual way. You hand it a set of labelled example rows (the context) and it predicts new rows by comparing them to those examples.

Concept drift is when the real-world rule changes over time. For example, customer behaviour shifts and the old examples no longer describe it.

The problem you study: TabPFN uses whatever context you give it. If the context is full of old examples from before the change, its predictions get worse. The question is whether choosing the context rows more carefully fixes this.

That is the whole project: which rows should TabPFN see after the world changes?

The methods (your mentor will ask about these)
Vanilla (P0): randomly sample rows from all history. This is the baseline. Everything is compared against it.
Sliding window (P1): use only the last 5 blocks. Old data is forgotten, so it adapts fast after drift. The cost is that it throws away useful data when nothing has changed.
Recency-weighted (P2): sample from all history, but recent rows are more likely to be picked. It is a softer version of the window.
ADWIN-triggered (P3): ADWIN is a drift detector. It watches the model's errors, and when they jump up it says "the world changed". Then you delete the old history. It adapts only when needed, so it should behave like vanilla when there is no drift.
Validation-guided (P4): test several strategies on the newest 2 blocks and use whichever is best. It only switches if the gain is over 5%. It is the most adaptive and also the most expensive.
kNN-context: pick the history rows most similar to the new data. It tests whether similarity is a better choice than recency.

Why these: they form a ladder from "do nothing" (vanilla) to "always forget" (window) to "forget when needed" (ADWIN, validation). That lets you answer whether adaptation helps, and whether it costs you when there is no drift.

The two metrics
Recovery time: how many blocks after the drift until error is back within 10% of its pre-drift level. Lower is better.
No-drift regret: how much worse a policy is than vanilla when nothing changes. It checks that your fix doesn't hurt in calm periods. Lower is better.
