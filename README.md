# TabPFN under concept drift

When data drifts, which past labelled rows should TabPFN see as its context? This project compares
six training-free context-selection policies on synthetic drift streams and three real datasets,
against three retrained baselines.

## Website

The presentation website is a static page in `site/`. It works offline and opens by double-clicking
`site/index.html` (no server, no internet, no build step).

**Regenerate the page data** after any change to the results:

```
python -m eval.make_report      # results/summary.csv and site_data/results.json
python -m eval.make_ablation    # results_ablation/ablation_summary.csv (only if you have ablation runs)
python -m eval.make_site        # site/data.js  (the page reads all its numbers from this file)
```

**Open it:** double-click `site/index.html`. Dark is the default theme; the button in the top bar switches
to light, and the choice is remembered in the browser.

**Check it:**

```
python tests/test_site_numbers.py          # every number in the site text traces to results/summary.csv
cd tests && npm install && node site_check.js   # browser check: text, console, network, accessibility, keyboard
```

`site_check.js` uses the Chrome or Edge already installed (set `CHROME_PATH` to choose another browser).

**Deploy:** it is a plain folder of static files, so any static host works. The simplest is Netlify
drag-and-drop: open https://app.netlify.com/drop and drop the `site/` folder onto the page. Note that
GitHub Pages for a private repository may need a paid GitHub plan.

The older Gradio app (`python app/app.py`) is kept as a backup.

## Credits and reproduction

### Repository layout

| Folder | What it holds |
|---|---|
| `common/` | shared contract: constants, result columns, method names |
| `data/` | synthetic drift streams and the real-dataset loaders (raw files in `data/raw/`, not committed) |
| `methods/` | TabPFN wrapper, the six context policies, the baselines |
| `eval/` | test-then-train runner, metrics, report, figures, ablation, findings and site builder |
| `results/` | one CSV per run, `summary.csv` and the PNG figures |
| `results_ablation/` | the ADWIN delta sensitivity runs and their summary |
| `notebooks/` | Colab notebooks that run real TabPFN on a GPU |
| `site/` | the presentation website (`data.js` is generated) |
| `app/` | the Gradio app, kept as a backup |
| `tests/` | site checks: numbers against the summary, and a browser check |

### Commands, in order

1. Baselines (local, no GPU): `python -m eval.run_baselines`
2. TabPFN policies (Colab GPU): `notebooks/colab_run.ipynb`, `notebooks/colab_real.ipynb`, `notebooks/colab_ablation.ipynb`
3. Summary table and site data: `python -m eval.make_report`
4. PNG figures: `python -m eval.make_figures`
5. ADWIN sensitivity table: `python -m eval.make_ablation`
6. Website data: `python -m eval.make_site`
7. Backup app: `python app/app.py`
8. Open the website: double-click `site/index.html` (works offline)
9. Checks: `python smoke_test.py`, `python tests/test_site_numbers.py`, `cd tests && npm install && node site_check.js`
